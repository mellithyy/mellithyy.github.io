Event-Day Reports

Hourly KPI reports that fill themselves on Ramadan, Eid and concert days

The problem

On big event days, such as Ramadan, Eid and concerts, engineers filled the hourly KPI reports by hand.

What I built

A tool that reads each hour’s network export, fills every region’s report template and sends it on the hour.

The result

About 98% less manual data entry on event days.

What it is

At Nokia, 2023 to 2025: a Python tool for event days. Every hour of a big event it reads the network’s KPI export, fills each region’s report template and sends it to the region’s team, so nobody copies numbers by hand through the night.

The question

During big events, such as Ramadan nights, Eid, New Year, a large concert or festival, or a VIP visit, every regional team has to send an hourly status of the sites that cover the event: traffic, call setup success, drops, availability and throughput, for 2G, 3G, 4G and later 5G.

Before the tool, engineers opened the hourly NetAct report export, found the right hour and copied the numbers into each region’s template by hand, every hour, often all night. The question: could each template fill itself from the export and go out on time, for any event and any region?

What it does

Templates per region

Each team keeps its own Excel template: its layout, its KPIs and its site groups. Every KPI cell holds a short formula, and the tool reads it, so a new event or a new KPI needs a new template, not new code.

An event night, hour by hour

Each hourly report shows every KPI now and its change against the same hour seven days before. In this illustrative night, call setup success on one site group dips at 22:00, and that is the cell the report showed as a drop.

A report every hour, on the latest complete hour

The export arrives a few minutes after each hour, and its newest hour is sometimes still filling. The tool then uses the last hour that every site group has, so the report goes out on time and never half empty.

How it works

  1. 01Read every technology sheet The hourly export is one workbook with a sheet per technology, 2G, 3G, 4G and later 5G: every KPI per site group, hour by hour, seven days back. The tool reads each sheet and skips the report’s own notes.
  2. 02Merge on hour and site group All the sheets are joined into one table on the hour and the site group. An outer merge keeps a group that only some technologies cover, so a group with no 5G still gets its report.
  3. 03Find the latest complete hour The newest hour in an export is often still filling. The tool takes the latest hour in which every site group has data, so a report never shows a half-empty hour.
  4. 04Fill the template’s placeholders The tool finds each technology block in the template, reads the site groups under it and works out every cell: {{…}} for the value now, :{{7d}} or :{{7d%}} for the change against the same hour seven days before.
  5. 05Write each problem into its cell A division by zero, an unknown site group or too little history becomes a short message in that cell. The rest of the report still fills, and nobody is left with a crash and no report.
  6. 06Send it every hour Each region’s report is saved with its hour in the file name and goes out to the region’s team, every hour of the event.
Read from each template, not written in code
  • Which KPIs, in which cells
  • Which site groups, and their display names
  • Who receives the report, and its subject

How I checked it

Before a report goes out, every cell holds either a number or a short reason. Three checks are part of the fill:

  • The hour used is the latest one where every site group has data, never an hour still filling.
  • A change against seven days before needs those hours in the export; without them the cell says there is not enough history.
  • A division by zero, a wrong formula or an unknown site group becomes a message in that cell, and the rest of the report still fills.

What I would do differently

I would replace Python’s eval with a small parser that only accepts KPI names and arithmetic, add tests with sample exports and templates, and keep a log of every hour’s reports in one place.
