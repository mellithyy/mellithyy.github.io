No-Code KPI Decks

A PowerPoint deck from one Excel settings sheet

The problem

Every new KPI deck needed a programmer to write its charts in code.

What I built

An engine that builds the PowerPoint deck from a template and one Excel settings sheet, and checks every row first.

The result

A new deck without code: 47 charts from 52 equations, 5 chart types in 10 layouts.

FieldTelecom, for a mobile operator in Egypt
Year2025, at Nokia
DataDaily and hourly KPI data, 2G to 5G
CodePrivate: it runs on the operator’s data

By the end of August 2025 one settings file described 47 charts from 52 equations, and the user guide explained every rule and every warning. A new deck, or a new chart in an old one, became a change to a template and a spreadsheet, not to the code.

What it is

At Nokia, 2025: a Python engine that builds a KPI PowerPoint deck without code. An engineer names the charts in a PowerPoint template and describes each one in an Excel settings sheet; the engine works out every equation on the network’s KPI data and puts each chart in its place.

The question

Until then, each KPI deck was built by its own Python script: its charts, formulas and layout were all written in code. The regional reports, on the same daily KPI data, worked well, but a new deck, or even one new chart, meant changing code.

The question: could any engineer build a new deck by editing a template and a spreadsheet, with checks strong enough that a mistake in a row shows up as a clear warning instead of a wrong chart?

What it does

Charts as rows

The chart’s title in PowerPoint is its id. The same id in the settings sheet gives the chart type, daily or hourly, the site groups to show, the equations and the axis of each line. The equations sit on a second sheet, so one formula can serve many charts.

Different decks, one engine

A deck is only a template and a settings file. In this illustrative example four decks come from the same engine: their charts differ, the code does not. One chart in the hourly deck had a bad row and drew a warning in its place.

5 chart types in 10 layouts

Line, Overlay, Line-Area, Pie and Stacked Bar, each with its options: one or two axes, several days on one 24-hour axis, shares that add up to 100%. They all share one style, so a deck looks the same whoever set it up.

How it works

  1. 01Name the charts in the template In PowerPoint, the engineer puts a chart where it should go and gives it a short id as its title. The template keeps its own design; the engine only looks for those ids.
  2. 02Describe each chart in the settings sheet One row per chart on the first sheet: the id, the chart type, daily or hourly, the site groups, the equation ids and the axis of each line. The second sheet holds the equations: an id, a formula over KPI names and a legend name.
  3. 03Work out each equation on the KPI data The engine reads the daily and hourly KPI tables, prepared from the NetAct exports for 2G to 5G, with about 70 KPI columns. Each formula is worked out with pandas for the chosen site groups; a formula that is just one KPI name is copied as it is.
  4. 04Draw each chart into its placeholder Each chart type has its own drawing in Plotly, all in one shared style: one or two axes, several days on one 24-hour axis, or shares that add up to 100%. The picture is made at the placeholder’s size and put exactly where the placeholder was.
  5. 05Check every row, and warn instead of guessing Before drawing, each row is checked in order: a known chart type, day or hour, site groups that exist, equations that exist and have a formula, and axes that make sense. A failed check draws an error or warning chart with the reason in that place and writes it to the log; the other charts still draw.
  6. 06Write the user guide A user guide, version 1.0 from August 2025, explains the template rules, every settings column, the chart types and each error and warning, so an engineer can build a deck without reading the code.
Set in the template and the settings sheet, not in code
  • Which charts, and where on which slide
  • The chart type, the site groups and the axes

How I checked it

Every chart either draws as described or says in its place why it did not. The checks run on every row, in order:

  • The chart type must be one the engine knows: a missing type draws an error chart, an unknown one a warning chart.
  • Every site group must exist in the data, and every equation id must exist with a formula; otherwise the chart’s place says which one is missing.
  • A chart split over two axes needs exactly two equations, and each axis setting must name one of them.

What I would do differently

I would move the file paths out of the code into the settings, run the data preparation in the same step, and add tests with a small sample template and settings file, so every check is proven on its own.
