KPI Report Engine

Daily and hourly network reports for four regions, built and mailed by code

The problem

Four regional network teams copied figures from thousands of CSV files into their KPI reports by hand, every day.

What I built

A Python and SQL engine that reads the network’s exports, applies the team’s KPI formulas and mails each region its report, daily and hourly.

The result

About 85% less manual reporting work. Every team has its report in the morning.

FieldTelecom, for a mobile operator in Egypt
Years2024 to 2025, at Nokia

What it is

At Nokia, 2024 to 2025: a reporting engine that reads the network’s own exports, applies the team’s KPI formulas, draws the charts and mails each region its report.

The question

The network performance teams of a mobile operator in Egypt, one for each of four regions, follow 2G, 3G, 4G and 5G through KPI reports: traffic, call setup success, dropped calls, day by day and hour by hour.

Before, those reports were put together by hand from the network’s exports, thousands of CSV files a day. It was slow, repeated work, and every morning report waited for someone to build it.

What it does

Daily regional reports

Every morning each region gets its own report, built on a template the team designed: the same pages in the same order, so an engineer knows where to look. The KPI formulas are the team’s own, kept exactly as they defined them.

Call drop rate%, threshold 1.0

One illustrative month, four regions. Each region keeps its own level and weekly rhythm; the East has one bad day, day 18, in amber.

Every technology on one page

Traffic is also split by technology, 2G, 3G, 4G and 5G, stacked, so the share of each one shows at a glance. 5G joined the reports in 2025.

An hourly report

Through the day an hourly report shows each hour against the same day last week. Its newest hour is two hours back on purpose: the network’s hourly export is complete only up to then.

An incident report, against a reference week

For a major outage in July 2025, an on-demand hourly report set every hour against the same hour and weekday of a reference week picked before the outage, so the team could see how far the network fell and when it came back.

Reports per controller

On request, the same KPIs per controller, the BSCs and RNCs that run 2G and 3G inside a region, to find which part of the region carries a problem.

A history file for long trends

The long trend charts read about five months of reviewed daily values from a history file kept in Excel, and the newest days from the fresh exports. Where the two disagree on an old day, the history file wins.

Late data: wait and look again

Before building a report it checks that the newest exports have arrived. If not, it waits ten minutes and looks again, up to three times; if they are still missing, the run stops rather than send a half-empty report, and it is run again by hand once the data is in. A missing day stays a gap on the date axis, never a zero, and one chart that fails never stops the rest of the report.

How it works

  1. 01Network exports Every hour: 2G, 3G, 4G and 5G counters as zipped CSV files in a shared folder
  2. 02Freshness check Is the newest hour in? If not, wait ten minutes and look again, up to three times; still missing, the run stops
  3. 03Read and merge One table per technology; on a repeated row the newest export wins; the history file adds the long past
  4. 04KPI formulas The team’s formulas, read from a config file, never rewritten in code
  5. 05Charts on the template The team’s PowerPoint template decides the pages; each chart is drawn and put in its place
  6. 06One mail per region The daily and hourly reports to every team; on request, an incident report or a report per controller
Kept in config files, not in code
  • KPI formulas

  • Recipients and switches

How I checked it

Before the teams relied on it, its numbers were checked against the reports made by hand.

What I would do differently

I would move the long history from the Excel file kept by hand into a small database early, so the trend charts never depend on someone editing a file.
